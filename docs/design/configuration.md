# Configuration and live tuning

All commands below run from the game repository root. JSON in [`Config/`](../../Config/) is authoritative; tables describe shipped values, not fallback defaults. Presentation colors, style and Shmup layout are covered in [presentation](presentation.md).

## Inspector layout

F1 / Select / Share opens the movable/resizable Gameplay controls. **Configuration...** opens the tuning tool; **Diagnostics** toggles the secondary read-only diagnostics. Those two actions share the initial right-hand tool slot and hide the other tool, rather than opening competing windows on top of one another. Drag title bars to move windows and edges to resize them. Diagnostics can also collapse to its title bar.

| Window | Initial physical-pixel bounds | Contents |
| --- | --- | --- |
| Gameplay | `(16, 16)`, `360×420` | Running/Paused, Pause/Resume and Restart; selected-mode radios; Shmup widening |
| Diagnostics | `(392, 16)`, `440×480` | Optional state/run facts, elapsed-frame history and expandable technical readings; initially hidden |
| Configuration | `(392, 16)`, `840×640` | Live tuning, explicit structural reset, Save changed, Discard and Reload |

At 1280×720 the initial Configuration window shows sidebar navigation beside Gameplay without overlap. On smaller displays such as 960×540, bounds recovery keeps Configuration reachable but it may overlap Gameplay; move/resize it as needed, and narrow panels switch to stacked category selection. Normal inspection has no test-image preview or PNG requirement. Diagnostics starts hidden (`diagnosticsVisible: false`); when opened, Frame history starts open and Rendering, Text cache and Font start closed. History reports host-loop elapsed milliseconds, not GPU duration or simulation-step timing, with min/mean/max over at most the explicit `historyCapacity` samples (shipped: 240; accepted: 1–65,536). New elapsed observations overwrite the oldest; UI cancellation/recreation does not itself collect samples. Shmup reports actual timing, geometry, HP/counts and pause state. Widening is disabled while paused or at maximum width; its stable range cannot narrow the current run.

`Config/inspector.json` owns initial bounds: root `left/top/width/height` configure Diagnostics, and required `gameplayWindow: { "left": 16, "top": 16, "width": 360, "height": 420 }` configures Gameplay. Required `configurationWindow: { "left": 392, "top": 16, "width": 840, "height": 640 }` seeds Configuration. Custom inspector JSON must include both complete window objects. Immutable settings objects are validated before native allocation and passed unchanged to the UI. Bounds are starting positions, not locks: moved/resized bounds, selected configuration category, group choices and diagnostics visibility survive panel toggles and context recreation within the running application. Breakout retains that state as the consumer; it does not rely on native context survival. Smaller framebuffers/DPI changes recover reachable bounds. A new launch starts from JSON again; persistence remains application-owned and no docking system or layout files are written. Custom inspector files must also supply `diagnosticsVisible`, `historyCapacity`, `theme` and `feedback`; legacy image fields are not part of the normal schema. `theme.colors` contains twelve explicit native normalized straight-RGBA tokens; `theme.metrics` supplies font-relative spacing, rounding, borders and disabled alpha. Those validated immutable kit objects are shared with the inspector and application controls. They neither change font roles nor reinterpret colors as PNG/sRGB bytes. Appearance edits use the existing Save-and-relaunch policy, not a hidden live settings channel.

See [validation and evidence limits](../engineering/validation.md) for layout test coverage and visual-testing limitations.

## Configuration controls

Open **F1 / Select / Share → Gameplay → Configuration...** and choose a category: Shmup, Breakout, Rendering, Appearance, Audio, Input, Physics & workers, Window, or HUD & tools. Only categories with selected source files appear. Wide panels use side navigation; narrow panels use a selector above the settings body. Navigation and Save/Discard/Reload stay outside the independently scrolling body at normal sizes. If the shell itself exceeds a short/narrow viewport, native shell scrolling keeps its actions, notices and category selector reachable. Labels/editors align when space permits and stack at narrow widths. Shmup starts directly at Ball tuning; Window and Rendering expose their main controls without a redundant file-level disclosure. Appearance groups palette/roles, shape styling and trails; Physics & workers groups clock/solver and execution settings. Other nested objects remain expandable for less common fields. Brick shapes/quarter turns have checkboxes; palette colors have native color editors and semantic roles have palette selectors. Values originate from the selected JSON files, not a second set of UI defaults. Input arrays other than shape/rotation choices retain their entry counts. Rejected edits and reset/relaunch counts stay visible; Help contains detailed policy and pending reasons. Source paths are disclosed within the selected tool body.

Valid live edits take effect automatically at the next owner update, outside ImGui drawing. A whole file is no longer treated as requiring a restart: each field shows its effect and any reset/relaunch reason.

| Field effect | Behavior |
| --- | --- |
| Live | Updates the running settings without replacing the session/world or resetting time, progression, entities, pause, input latches or unrelated trail history. Colors/style, input, audio and ordinary gameplay tuning do not need a new run. |
| Future spawns/defaults | Stores new choices/defaults without rewriting existing lives; for example, brick health and shape choices apply to newly spawned bricks. |
| Reset required | Tick frequency/catch-up capacity, execution workers, logical arena/brick topology, pool capacities, brick size/grid pitch and Shmup bounce/sensor mode. **Reset & apply pending** intentionally starts a fresh run and retains mode/manual pause. Inactive-mode geometry can become next-mode settings without resetting the current mode. |
| Relaunch required | Shared-mesh allocation budgets and renderer-owned overlay/inspector resource settings remain pending; the current package exposes startup-only configuration. |

Live coverage includes ball speed/radius/damage/rate/wall limits, avatar movement/radius/contact tuning, difficulty/noise, input deadzone, audio, all colors/style/trails, physical window dimensions, and physics substeps/contact stiffness/damping. Current brick health/shape/rotation and appearance remain per-life when spawn defaults change. Lowering avatar health clamps current maximum/HP; raising it never heals or resurrects.

Pending reset/relaunch and unsaved markers are independent. Live candidates merge onto the currently applied structural settings, so pending geometry/resource edits cannot leak into the running world or force an unrelated reset. Invalid intermediate edits retain previous valid settings and report errors. Numeric fields use game units, units/second, seconds or their named ratios; integer-only schema fields reject fractional values. Press **Enter** to commit physical window width/height and the frame rate cap; intermediate typed digits do not resize the window. Audio changes use the existing silent-output diagnostic if a device is unavailable; unrelated edits do not reopen audio devices.

**Save changed** only persists the staged JSON; it does not reset the run or apply pending structural/relaunch fields. It validates all staged files, preserves relative asset-path spellings, checks for external edits and atomically replaces each changed file. Multi-file failures attempt rollback and report any partial save; this is not a filesystem-wide transaction. **Reload** discards drafts and validates disk files; **Discard** returns to the last loaded/saved source. Their valid live values take effect automatically, while structural/relaunch changes still wait for the appropriate explicit action. No automatic settings or layout writes occur.

The selected absolute paths are shown in the panel. Direct application launches normally select executable-directory `Config/` copies; saving those copies is not durable across clean/redeployment. From the project directory, **`--project-configs`** selects source `Config/` files for implicit paths. The coordination workspace's **`play.cmd`** supplies this flag automatically. Explicit per-file `--*-config <path>` overrides still win and saves target exactly those files. Apply uses in-memory production parsing/cross-validation and does not need write access to the source directory.

## Control presentation and field recovery

Primary labels retain subdued units but omit per-field Live/Future/Reset/Relaunch lines. A `*` suffix marks a reset/relaunch field whose draft differs from the running configuration. It clears on successful application or reversion to the applied value, not merely on Save or source Reload; relaunch-only values remain marked through structural Apply. Policy details stay in hover help and the panel's pending notices. Common speed/radius/fire-rate quantities use native double-precision drags, gain/opacity use sliders, and known integer fields use signed 64-bit editors rather than float conversions. Drag/slider bands are convenient interaction ranges, not an additional schema: Ctrl-click enters an exact value outside the band and production validation remains authoritative. Unsupported quantities retain an exact generic editor. Existing fractional invalid drafts for integer fields remain repairable instead of being silently truncated. Physical window size and cap retain Enter-to-commit behavior. The Window page distinguishes the configured cap (**Unlimited** for zero), requested VSync and the last effective native present mode; an unlimited cap does not disable VSync.

The visible **...** field button opens **Restore from source**, **Copy value**, and useful field-specific presets. Right-click is an optional shortcut, not the only way to find actions. Source recovery stages only that literal-key field from the selected loaded/saved source snapshot; it is not a factory default, whole-document Discard, implicit Save or reset. Save and Reload update the recovery snapshot; unrelated draft changes remain intact. Array controls can recover the selected source array, while generic entries also support per-entry recovery. Missing source fields cannot be invented by recovery. Copy queues an owned JSON value string for the host to write to the clipboard outside drawing. Presets are explicit suggestions (for example cap values and fractional fire rates), not fallback runtime defaults or promises that every current coupled configuration will accept them.

Structured help explains the effect, exact-input interaction and why a disabled widening control is unavailable; critical failures never depend on hovering. A single compact recent-operation title may appear after an explicit operation or copy. Detailed notices stay in the scrolling **Recent actions** disclosure, not a growing fixed header. Required `feedback` preferences supply capacity, combined text limit and success/information lifetimes (shipped: 4 notices, 2048 characters, 3/5 seconds). Application admission accepts capacity 1–1024 and text limits 128–65,536; lifetimes are positive finite seconds. Host time drives expiry even while tools are hidden, repeated IDs coalesce, and full capacity evicts the oldest. Long optional details are safely bounded without splitting Unicode pairs. Successful automatic drag updates do not generate success notices. Rejections, conflicts, pending reset/relaunch and runtime diagnostics remain visible persistent state after transient feedback expires. The fixed header uses short sanitized summaries; Help contains complete sanitized, selectable diagnostic text in bounded-height native scrolling widgets. Raw managed error state is retained unchanged. Presentation text/UTF-8 is rebuilt only when the status or runtime diagnostic changes, so long messages cannot flood the header or trigger per-frame encoding. A live draft restored to already-applied values quietly clears its resolved live rejection; it does not replay a stale failure or hide unrelated unresolved source-operation/clipboard failures. Outcomes distinguish user operations, live attempts and external failures, and failed Save/Apply outcomes retain the requested action. A successful retry or validated Reload resolves its source-operation failure; the clipboard owner clears its external failure after a successful copy. There is no timed confirmation for ordinary gameplay or window-size edits; no display-mode editor is implemented.

## Initial window configuration

`Config/window.json` is the only production default source for initial **physical window** dimensions: required positive integer `width` and `height`, required boolean `vsync`, and required integer `frameRateLimit` in **0–1000** (0 is unlimited). The shipped policy is VSync on with no additional frame cap. These are independent of `Config/gameplay.json`'s logical canvas; fit/letterboxing still derives from that canvas and the actual framebuffer. Both game and gallery require this file. `--window-config <path>` independently overrides it, using caller cwd for relative paths; default lookup uses the executable directory. Build and publish copy it alongside the other configuration assets. Startup reports selected absolute path, requested dimensions and actual created window/framebuffer dimensions.

The immutable `WindowSettings(int width, int height, bool vSync, int frameRateLimit)` has no defaults or mutable properties. The strict loader rejects missing/unreadable files, absent/null/unknown/duplicate/escaped-duplicate fields, wrong types and nonpositive/out-of-int-range dimensions **before GLFW or a native world**. There is no fallback or partial merge. Physical dimensions, VSync and frame rate cap can be edited live through the Configuration panel; external files are not watched. Gallery still loads no implicit physics/game/input/colors/style files; explicit overrides remain validated. `--cleanup-self-test` exits before any configuration lookup or native startup. Positive integer representability does not promise OS/GPU support for arbitrarily huge windows.

### Presentation timing

In Configuration → **Window**, **VSync** applies immediately; **Frame rate cap (0 unlimited)** commits on Enter, so typing 144 does not temporarily cap at 1 FPS. Both are LIVE even while paused, preserve the run and input latches, and require explicit Save for persistence. Reload/Discard also apply valid live values. Startup honors JSON without the editor.

VSync on explicitly selects FIFO; off requires supported Immediate (tearing possible), never a silent FIFO/mailbox fallback. Capability preflight rejects unsupported requests before applying runtime settings. A policy change schedules swapchain recreation at the existing owner-thread idle boundary without resizing the GLFW window or restarting gameplay.

The app's monotonic render budget subtracts all work already spent, including Vulkan synchronization/presentation waits. The remaining interval uses event-pumping waits of at most 10ms, stops on close, and never accrues catch-up debt. Unlimited cap does not disable VSync; both enabled are bounded by the lower available throughput. Minimized/nonpositive framebuffer paths retain their existing 50ms idle wait instead of double waiting. Pacing time appears in the next loop's real elapsed interval; fixed simulation Hz remains unchanged. Very low caps can invoke the existing maximum catch-up/drop policy rather than silently changing physics timing.

## Shmup rendering path

**Configuration → Rendering → Rendering path** selects **Shared meshes** (shipped default) or **CPU-built triangles**. Valid choices apply on the next owner update, including while paused, without Save or a new run. Ball/compound-brick shapes, colors, movement, trail selection, aim, HUD and ImGui ordering remain unchanged. Unsupported geometry or an exhausted mesh cache uses CPU triangles in the same ordered stream. Classic Breakout keeps its rounded bricks and existing triangle path. VSync and frame-cap controls remain independent under WINDOW.

`Config/rendering.json` is required for game and gallery; `--rendering-config <path>` follows the same executable-directory, `--project-configs` and explicit-override rules as window configuration. Build/publish copies it automatically. All root/nested fields are required and strict: `path` is exactly `sharedMeshes` or `cpuBuiltTriangles`; `limits` contains positive integer `meshCount`, `cpuBytes`, `gpuBytes`, `instances`, `operations`. Missing, unknown, duplicate, null, wrong-type and out-of-range values reject before GLFW/native allocation, including in editor-free builds.

The shipped bounds are 128 cached meshes, 8 MiB CPU mesh/selection storage, 8 MiB GPU meshes, 8,192 instances and 16,384 ordered operations. CPU storage includes an 8 KiB fixed selection reservation; instance/operation arrays are separately bounded by their capacities, not included in the mesh-byte budgets. Admission bounds are `meshCount <= 4096`, `8192 <= cpuBytes <= gpuBytes <= 256 MiB`, and instances/operations each at most 1,000,000. For live path switching, instance capacity must cover configured Shmup max balls plus max bricks; operations must cover twice that sum plus 16. These are safety limits, not alternate defaults. Valid zero-cache-headroom budgets deliberately fall back rather than dropping shapes.

`circleDetail` is also required: `mode` is exactly `automatic` (default) or `fixedSideCount`, and `fixedSides` is a multiple of four from 8 through 4096 (inactive default 12). **Circle detail → Automatic / Fixed side count** applies to filled balls in both Shmup paths and classic; **Side count** is shown only in Fixed mode. Automatic rounds up to a multiple of four and retains the ≤0.25 physical-pixel curve target. Fixed uses exactly the selected count even for large balls: intentional faceting is not an automatic-quality failure. Both modes retain finite/precision/orientation/resource guards; ordered fallback uses the same selected count. Physics circles, avatar detail, rounded bricks, outlines and patterns are unchanged. Circle-detail edits are LIVE while paused, without resetting time/session or saving; explicit Save/Reload/Discard/conflicts remain. Movement/color changes reuse geometry; mode/count/viewport changes select only the needed resolution in the existing bounded caches.

`path` and `circleDetail` are LIVE. Resource budgets are immutable/startup-only: changes remain pending through **Reset & apply**, require explicit **Save changed** and relaunch, and never replace native policy during Draw. The same startup limits object drives the persistent producer and ordered renderer frames; changing paths retains its bounded warm geometry. Unrelated configuration reparsing reuses equal authoritative brick decompositions. Restart/mode changes retain only bounded geometry, never simulation lives, snapshots or borrowed frames. Disposal releases the CPU owner at app exit; renderer-owned static buffers follow the existing fence/device lifetime. Reload/Discard and external-edit conflicts use the normal workspace semantics above; invalid edits preserve the last valid publication.

## Physics configuration

`Config/physics.json` is the only production default source for physics timing/tuning and is copied into build/publish output. Select another file with `--physics-config <path>`; explicit relative paths resolve against the caller's working directory. Showcase-only modes do not load implicit physics, but validate an explicit override.

See the [physics guide](../engineering/physics.md) for every setting, shipped values, strict validation, live-versus-reset behavior, adaptive Shmup intervals and their interaction with solver substeps. External files are not automatically watched; the Configuration panel's Reload/Discard and explicit reset rules apply as described above.

## Gameplay and input configuration

`Config/gameplay.json` and `Config/input.json` are the only production default sources for ball/arena geometry and stick deadzone. Like `Config/physics.json`, they are copied into the executable's `Config/` directory on build/publish and loaded before GLFW/native world creation. Edit the source files and build/run again, edit deployed copies, or choose independent overrides:

```powershell
dotnet run --project src/App/BrutalBreakout.App.csproj -- --gameplay-config ./my-gameplay.json --input-config ./my-input.json
# All three overrides can be combined:
dotnet run --project src/App/BrutalBreakout.App.csproj -- --physics-config ./my-physics.json --gameplay-config ./my-gameplay.json --input-config ./my-input.json
```

Every section/field is required; there is no partial merge, C# fallback or parameterless settings constructor. Unknown/misspelled, duplicate (including escaped names at nested levels), missing, null or wrong-type fields fail with file-path context. Each option accepts one path; relative paths use caller cwd. Showcase-only modes need neither implicit gameplay nor input files, but validate any explicit overrides (window configuration is always required). External files are not watched. Use the Configuration panel for field-level live edits or Reload; structural fields require explicit reset.

| File / section | Required fields and meaning |
| --- | --- |
| `Config/gameplay.json` / `arena` | `width`, `height`: logical canvas; `left`, `top`, `right`, `bottom`: inner wall faces; `wallThickness`: wall thickness in logical units. |
| `Config/gameplay.json` / `ball` | `radius`, `speed`: logical radius and units/second; `spawnX`, `spawnY`: reset center; `initialAimX`, `initialAimY`: finite nonzero direction, normalized once. |
| `Config/gameplay.json` / `breakout` | `startingBalls`, `catchZoneHeightFraction` (canvas fraction measured up from bottom), `maxBouncesWithoutBrick` (0 disables expiry), `bricks`: rectangles with `x`, `y`, `width`, `height`. |
| `Config/input.json` | `stickDeadzone`: radial deadzone in **[0,1)**, validated after float conversion; the boundary is inactive. |

Ordered walls including thickness must fit the canvas, radius must leave a nonempty playable area, and spawn must fit the radius-inset bounds. Invalid/degenerate native float geometry and unsafe speed/timestep combinations reject before a world is allocated; errors for combined physics/gameplay incompatibility identify both paths. Validation establishes numerical representability, not stable physics for every extreme setting.

The same immutable settings drive native walls/circle/velocity, reset/casts, drawing and pointer/DPI fitting. Native speed/radius/positions are **derived via the one unit conversion**, never separately authored meter defaults. Cast reach derives from configured geometry; native maximum linear speed does not silently undercut requested launch speed. Rendering uses the configured inner faces and thickness rather than a second wall layout. The required breakout section validates a nonoverlapping layout inside the walls, above the catch line and clear of the spawn circle. Explicit null breakout settings are only for library physics-reference tests, not a production JSON fallback.
